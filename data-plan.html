Qwen Pixel-Edit：数据构建计划 V2

更新：2026-11-25。本文是新的执行方案，生产配额和采样比例均为待验证起点。 当前 SFT goal 保持暂停；本次更新没有启动训练、采集或 teacher 生成任务。

1. 目标与边界

训练 Qwen3.8-27B：原图 + 英文编辑指令 → 单次回答中的证据、计划和完整 Python 程序 → 程序读取原图 RGB，产生编辑后的 RGB/PNG。

  • 主线只做 image editing，包括照片、英文信息图和科研图编辑。
  • 主数据采用 one-shot 格式；多轮 agent/错误恢复数据保留为独立诊断实验。
  • 程序使用 PIL、NumPy、经典 OpenCV 等透明的像素运算；不调用预训练图像生成器、 编辑服务或隐藏的定位函数。
  • InstructPix2Pix 停用，覆盖采集、RFT/TI、新快照、改写/增强派生版本。 已生成数据与历史实验保留。
  • RGB-only、image+RGB 是后续独立输入表示实验。核心资产保持同一真实 RGB， 输入视图、分辨率、token 预算和 teacher 条件另行固定，不直接混入首版主实验。

2. 数据源与首版生产目标

现有约18,500行英文监督是历史+新增候选库存，尚不等于 V2 的精选训练集。 先复核存量，再补充不足；首版目标是 20,000条严格合格监督、至少10,000个 独立编辑任务。同任务的 RFT/TI 可以各计一行，另外报告原图/论文来源组数。

来源 20K 首版参考配额 责任
MagicBrush 8,000（40%） 人工指令与审核编辑作为照片核心；局部属性、增删替换
UltraEdit Region_Based_100k 4,000（20%） 区域编辑与丰富场景；原有 mask 用于构造/验证
AnyEdit 可用文本指令类型 2,000（10%） 补充背景、环境、结构编辑；排除依赖额外视觉参考的类型
MaskEdit Scene 1,000（5%） 补充场景局部编辑与保留约束
MaskEdit English Infographics 2,000（10%） 可读英文文字、布局和信息图
SciForma Editing 3,000（15%） 科研图组件、箭头、文字与结构一致性

这是采集优先级和产量目标，不是论文给出的最优来源比例。编辑类型覆盖优先于 同时凑齐来源百分比。不够的桶显示缺口，不用低质量样本、重复文件或别的任务冒充。 GIER 可作为下一轮实用修饰候选，先验证少量真实任务；本版不默认增加新来源。

3. 按任务建桶，避免只有简单改色

每个任务记录 domain、primary_type、operations、scope、difficulty。 科研图先归入科研图桶，英文信息图先归入文字/布局桶；照片再按主要编辑操作分类。 多操作保留完整 operations 列表，由审核确定主要类型，不重复计数。

主任务桶 首版参考占比 示例
照片属性与局部修饰 25% 改色、光照、纹理、局部模糊/修饰
照片对象删除 15% 移除指定对象并自然补全背景
照片对象增加/替换 15% 新增物体、替换物体；桶内分别记录两类
照片背景/环境 15% 换背景、天气、时间、整体光照
照片风格 5% 明确请求的绘画/视觉风格
英文文字/布局 10% 改文字、字号、位置、颜色、布局
科研图结构编辑 15% 改组件、箭头、标签，保持未请求的逻辑与数值

难度起点为60%单操作、30%双操作、10%三操作以上，属于待验证课程设计。 控制物体类别、场景、指令模板和同来源组的重复度。照片增删替换的缺口不能用 科研图中添加矩形/箭头来填充。当前代码无法可靠完成的样本标记原因并保留， 正式测试仍保留这些难任务，不能通过删测试难题提高成功率。

4. 先检查任务，再调用 teacher

保存原始指令与原始图片，生成两项独立标签：

  1. source_instruction_valid：对象、范围、变化和输出要求能从原图+指令确定。 标题式、非视觉、矛盾或无法消歧的指令进入待审。
  2. target_instruction_valid：目标实现了请求，且未产生不被允许的身份、布局、 背景、文字或数值变化。

原图+指令有效但目标错误时，可构造 source-only RFT 并按指令验证；TI 不使用该 错误目标，目标相似度指标标记不可用。纯拼写修正/消歧可以形成有来源记录的新 训练任务，不把错误目标的额外变化改写成“用户想要的操作”。原 benchmark 指令不改。

原始 RGB 资产保留原生尺寸与宽高比，统一 EXIF/透明度/RGB 转换后，让 teacher、 student 和执行器使用同一版本。模型观察视图可以按预算缩放，程序在原生 source RGB 上执行；目标尺寸/对齐变换必须记录。当前同尺寸运行路径无法处理的裁剪等 任务单列，不通过隐藏拉伸目标来伪造对齐。科研图/文字另测更高观察分辨率。

5. 每种来源都构造 RFT 与 TI

路径 Teacher 看什么 用途
RFT source + instruction 符合部署条件的独立解法
TI enrichment source + instruction + 合法 target RFT 已成功的任务也构造，得到可比较的配对监督
TI rescue 相同 TI 输入 在真实 RFT 语义失败后扩展可解决任务覆盖

每个候选是一条独立的 teacher API 回答。失败后换 teacher 或再次采样生成新 candidate ID，输入仍是任务本身，不加入失败代码形成 repair 对话。 任务有效性检查、程序执行、judge 是生产端验证步骤，其中 judge 可以有独立 API 调用；“单次”指 teacher 生成/学生推理，不是整条流水线只有一次网络调用。

Teacher 固定输出完整可见 JSON：visual_evidence、target_object、target_region、 editing_intent、editing_plan、preservation_constraints、executable_code、requires_inpaint。 证据来自 source；TI 也不能声称学生看到 target/mask 或依赖未提供的信息。 不采集/宣称隐藏内部思维链。程序必须完整定义 def edit(image)，读取 source RGB， 返回真实图像；正常 source 坐标/颜色参数允许，目标像素大数组或外部 target 读取禁止。

首版精选集合以 RFT/TI≈50/50 为生产目标；先向不足的 TI 分配约60%构造预算， 达到合格数量平衡后再调整。这是初始假设，不是已有实验结论。 每任务每模式最多保留两个不同策略的合格程序；主核心优先选一条 RFT、一条 TI， 其他策略用于明确的多答案/teacher 多样性实验，不靠容易任务堆行数。 API/队列/存储错误属于 pending；先恢复已有响应和判定，不当成语义失败触发 TI。

6. 入库要过 RGB 结果检查

V2 精选主训练标准：

  • 指令一致性、保留、画质各至少4/5，完整目标区域通过；要求 judge 完成且明确通过。
  • 局部任务检查漏改与越界；全局任务检查身份/构图/内容保留，不能要求全图像素不变。
  • 文字任务检查正确内容与可读性；科研图检查 Component/Arrow/Text 与未请求的数值、 关系。没有可靠验证依据时保持待审，不默认成功。
  • 程序 source-only、实际运行成功、尺寸/uint8 RGB/PNG 一致，排除不被允许的 no-op。
  • 保留 source 无关重建/target dump 的静态检查。局部任务可用不相关区域的输入扰动 检查输出是否保留该变化；普通坐标合法。旧“同代码翻转图可执行”不是语义泛化证明。
  • L1、DINO/CLIP 与 source/no-op 基线作为诊断；不能单靠正 L1 gain决定合格。

主 judge 尽量与生成 teacher 分开；边界/冲突案例交叉判定，不反复抽 judge 直到 过关。按来源×模式×类型抽查300条，误放率超过5%时先校准规则再扩量。 保存三个状态：LegacyPass（历史规则）、CuratedA（V2 严格合格）、PendingReview。 历史3/5、验证不足和失败数据继续归档，不修改历史 pass 标签来伪装质量提升。

保存源图片、原始与规范指令、teacher 完整可见响应、实际返回模型标识/请求信息、 prompt 版本、代码、执行环境版本、渲染 RGB、judge 版本、图像指标及全部失败原因。 缺少 usage/模型身份的信息如实标 unknown；不能编造价格或用于“同 teacher”对照。 策略可以有多种，但只保留验证过的像素编辑代码；不默认采用尚未通过质量验证的新算法。

7. SFT 输出与冻结

学生统一看到 source + instruction，RFT/TI 均监督同一固定 schema 的完整可见 证据、计划和代码。Target/mask、编辑后图、验证结果、teacher-only差异分析不放入 主 one-shot 输入。代码实际产出的 RGB 是验证/评估资产，不宣称普通文本 SFT 能 直接输出图像张量。多轮 agent 数据的真实工具观测与采样 token 保留在独立实验。

先按原图/论文图/编辑链来源分组，再产生全部 teacher、TI、改写和增强版本。 用原始ID、source/target RGB hash、近重复检查与人工复核排除跨来源验证泄漏。 训练只采官方 train；所有派生版本继承 source group 划分。

冻结前做代码/图片/语言去重、完整 native Qwen 编码审核、assistant-only/EOS 标签 与训练推理模板一致性检查。每个版本记录原生资产、行数、独立任务/来源组、 来源×类型×模式统计、数据/代码/环境 hashes。运行中的训练快照不修改。 采用任务优先的种子采样器/固定采样计划，避免同任务多 teacher 抢占曝光；报告 真实来源、模式、类型的 assistant-token 比例，不把库存行数或反复访问当新增数据。

8. 分阶段验证与扩大

  1. 存量复核：清洗现有18.5K候选，统计各桶严格合格数、来源血缘和 RFT/TI 缺口。 不预先宣布全部库存都可训练。
  2. 20K core：补足高质量/独立任务覆盖，冻结无 InstructPix2Pix 的版本。 做5K/10K/20K数据量对照和100/0、75/25、50/50 RFT/TI 配比对照。 配比实验只用两种模式都成功的同任务/同teacher；TI rescue 的覆盖作用单独比较。
  3. 50K→100K：只有严格质量与大验证集收益维持，才继续扩大。难类型不足时 优先补这些类型；已有数据上更多训练曝光另作计算量实验。

主要实验固定模型初始化、模板、执行器、质量过滤和总 assistant-token 预算； 另外报告固定训练曝光实验，区分数据多样性与更多计算。主结论至少复现两个 seed。

验证方案：MagicBrush 官方 dev 全量（公开528条版本，执行前核对）；UltraEdit、 AnyEdit各约200条 source-group holdout；MaskEdit场景/英文各约100条；SciForma Editing约200条图/论文来源隔离的编辑任务。除有已核实官方协议者，其余明确标为 自建验证。SciFormaBench-2K 的原始生成任务不直接冒充编辑 benchmark。 旧8/64案例属于已反复使用的开发集，最终官方 test/锁定测试组保持独立。

同时报告执行成功、已完成 judge 覆盖、语义成功、完整目标、保留、画质、文字/ 科研结构指标、benchmark目标指标、no-op与零样本基线及生成/执行成本。 未完成编辑计入模型失败；尚未完成的 API/judge 单列 pending，不冒充语义失败。 小样本涨几条或低 loss不作为继续扩量的唯一依据。

9. Teacher 与夜间资源

GPT-6.2-Sol/GPT-6.1-Sol优先高质量 TI、难照片与科研图；GPT-5.5以至少8并发承担 RFT广度和固定对照。Terra/Luna、DeepSeek/Seed先按类型实测成功质量与成本，再决定 承担哪些桶，不把每个任务盲目交给所有模型。

恢复执行后沿用已授权的北京工作日18:00–09:00、周末全天高并发；当前已配置的 61-Sol/62-Sol总上限56/44包含等待API，不是完成速度保证。根据真实队列、错误率、 延迟与合格样本/小时调整，保留已提交请求和原始响应，分片持续恢复。 按需读取数据分片、按 RGB hash复用原生资产，记录存储预算，避免把同图多轨迹 另存为多份图片。已有数据及受保护系统归档保留。
